# service 包说明

## 包职责
定义业务能力接口，承接 Controller 的需求并屏蔽实现细节。

## 为什么创建这个包
需求经常变，接口与实现分离可以降低改动成本：
- Controller 依赖接口，不依赖具体实现。
- 便于单元测试和后续替换实现策略。

## 类说明
### `UserService`
- 用户域业务接口：注册、登录、验证码登录、更新头像。
- 额外提供 `getOnly` 默认方法，封装“查询单条并限 1”语义。

### `CommonService`
- 通用能力接口：发送验证码、获取上传 URL。

## 开发时思考过程
1. 从用例角度定义能力边界（方法签名）。
2. 先有接口，再落地 `impl`。
3. Controller 只依赖接口，降低耦合和认知复杂度。
