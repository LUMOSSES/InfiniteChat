# constants.user 包说明

## 包职责
管理用户域业务常量，包括错误码和 Redis key 前缀等。

## 为什么创建这个包
用户域是高频路径，错误码和 key 前缀必须稳定且统一。  
集中管理可以避免：
- 同一错误多种编码
- Redis key 冲突
- 文案不一致

## 类说明
### `ErrorEnum`
- 作用：定义用户域错误码与错误消息（注册失败、验证码错误、登录失败、用户不存在等）。
- 思考：前后端协作需要稳定错误码，枚举是最直观方案。

### `registerConstant`
- 作用：定义注册验证码在 Redis 的 key 前缀：`register:code:`
- 思考：key 命名规范集中维护，便于排查和防冲突。

## 开发时思考过程
1. 先确定错误码分段策略（4xx 业务错误，5xx 系统错误）。
2. 把 Redis key 命名规范抽成常量。
3. service 仅引用语义化常量，避免手写字符串。
