# conf 包说明

## 包职责
放置认证服务的基础设施配置与请求拦截逻辑。

## 为什么创建这个包
需求上需要“安全入口约束 + 中间件装配”，这些逻辑不属于业务本身，应该集中放在配置层，避免业务层被污染。

## 类说明
### `Interceptors`
- 作用：注册并编排拦截器执行链。
- 思考：把拦截器挂载规则集中到一个地方，后续扩展审计/限流更容易。

### `SourceHandler`
- 作用：校验请求来源头 `X-Request-Source`，拒绝非法直连请求。
- 思考：要求所有请求经过 Gateway，避免绕开网关安全策略。

### `JwtHandler`
- 作用：校验受保护接口的 `Authorization` 请求头是否存在。
- 思考：先做最小可用防护；后续可增强为 token 真伪和过期校验。

### `MybatisPlusConfig`
- 作用：配置 MyBatis-Plus 拦截器（含分页插件）。
- 思考：把数据库框架配置集中，业务层不关心 ORM 细节。

### `MinioConfig`
- 作用：构建 `MinioClient` Bean，供上传 URL 生成使用。
- 思考：对象存储客户端属于基础设施依赖，必须 IOC 管理。

### `RedisConfig`
- 作用：自定义 `RedisTemplate<String, Object>` 序列化策略。
- 思考：默认 JDK 序列化可读性差，统一 JSON 序列化便于排查和跨语言兼容。

## 开发时思考过程
1. 先梳理安全关卡：来源检查、鉴权检查。
2. 再梳理中间件：MySQL、Redis、MinIO 的客户端初始化。
3. 最后统一放入 `conf`，做到“变更配置不改业务代码”。
