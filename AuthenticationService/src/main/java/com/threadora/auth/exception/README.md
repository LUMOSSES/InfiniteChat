# exception 包说明

## 包职责
定义业务异常类型，并在全局统一转换为 API 响应。

## 为什么创建这个包
需求上会有多类失败：用户错误、验证码错误、数据库错误、参数错误、系统错误。  
如果全部 `throw RuntimeException`，前端很难区分错误性质。

## 类说明
### `UserException`
- 场景：注册冲突、登录失败、用户不存在等用户域错误。
- 价值：携带业务错误码，前端可做针对性提示。

### `CodeException`
- 场景：验证码为空、过期、校验失败。
- 价值：将验证码问题从用户错误中单独抽离，便于统计和风控。

### `DatabaseException`
- 场景：保存/更新数据库失败。
- 价值：区分业务失败与基础设施失败。

### `GlobalExceptionHandler`
- 作用：统一捕获异常并返回 `Result`。
- 覆盖：
  - 自定义业务异常
  - 参数校验异常
  - 未知异常兜底

## 开发时思考过程
1. 先定义异常分类和错误码策略。
2. service 层只抛语义化异常。
3. controller 不 `try-catch` 业务异常，交给全局处理器统一收口。
